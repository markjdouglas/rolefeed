# RoleFeed

Finds senior operations roles in transport, logistics, mobility and aviation by querying
public applicant tracking system (ATS) endpoints for a curated list of 169 employers,
then filtering hard and grouping results by company size.

No scraping, no paid APIs, no LinkedIn. Five adapters, one employer list.

## Setup

```bash
/opt/homebrew/bin/python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Use the explicit Homebrew path for `venv`. Plain `python3` resolves to Apple's 3.9.6,
because macOS's `path_helper` puts `/usr/bin` ahead of `/opt/homebrew/bin` and
`brew shellenv` declines to prepend a directory already on PATH.

`source .venv/bin/activate` puts this project's Python first, so `python` means this
project with these packages. Run it in every new terminal tab; `deactivate` undoes it.

## Use

Resolve where each employer's job board lives. Run after editing `companies.yaml`.
Roughly three minutes.

```bash
python discover.py                  # everything
python discover.py --only charging  # one sector
python discover.py --workers 12     # more concurrency
```

Fetch and filter:

```bash
python fetch.py                     # matching roles, grouped by company size
python fetch.py --all               # every role, to sanity-check the filter
python fetch.py --size enterprise   # one size bucket
python fetch.py --sector freight    # one sector
python fetch.py --json              # also write data/jobs.json
```

If `fetch.py` returns little, run `--all` before assuming the code is broken. A thin
result usually means the filter is tight, not that the fetch failed.

Configure a Workday employer from its careers URL:

```bash
python add_workday.py "https://tenant.wd3.myworkdayjobs.com/en-US/Site_Name"
python add_workday.py --check       # verify every configured Workday employer
```

## Files

| File | Purpose |
|---|---|
| `companies.yaml` | The curated employer list, tagged by sector and size. This is the actual product — edit it often. |
| `companies.resolved.yaml` | Generated by `discover.py`. Employer → ATS → verified token. |
| `ats.py` | One adapter per ATS. All return the same dict shape. |
| `discover.py` | Probes token variants against the four public endpoints, concurrently. |
| `fetch.py` | Pulls, dedupes, filters, groups by size, prints. |
| `add_workday.py` | Turns a Workday careers URL into config, and verifies it. |
| `CLAUDE.md` | Standing brief for Claude Code. Read at the start of every session. |
| `SPEC.md` | What this is, what it deliberately is not, and why. |

## The five adapters

| ATS | Auth | Discovery |
|---|---|---|
| Greenhouse | none | token probe, both US and EU hosts |
| Lever | none | token probe |
| Ashby | none | token probe |
| SmartRecruiters | none | token probe, case-sensitive |
| Workday | none | **hand-configured** from a careers URL |

Workday is different in kind. It has no public API — the adapter calls the endpoint the
career site's own front end uses. Tenant, instance number and site name cannot be
guessed, so those employers need `add_workday.py` once each. It is also undocumented, so
treat a sudden drop to zero roles as suspected breakage rather than an empty board.

## Employer list

169 employers across ten sectors: ride-hail, micromobility, last-mile, freight,
fulfilment, EV charging, fleet and telematics, public transport, aviation and space,
autonomy.

Tagged by size, because results read better grouped by company type than as one pile:

| Bucket | Headcount | Count |
|---|---|---|
| `enterprise` | 5,000+ | 60 |
| `large` | 1,000–5,000 | 37 |
| `mid` | 250–1,000 | 42 |
| `scaleup` | 50–250 | 30 |

Anything under roughly 50 people is excluded. Headcounts are approximate.

Previous employers are excluded by design: Uber, Gett, Glue Home, Ontruck, ParkBee,
Otto Car, POSTX, Apolitical, Abercrombie & Fitch.

## Fixing an unresolved employer

`discover.py` guesses tokens, so some will miss. Open the careers page and read the URL:

| URL contains | ats | slug |
|---|---|---|
| `boards.greenhouse.io/acme` or `job-boards.eu.greenhouse.io/acme` | `greenhouse` | `acme` |
| `jobs.lever.co/acme` | `lever` | `acme` |
| `jobs.ashbyhq.com/acme` | `ashby` | `acme` |
| `jobs.smartrecruiters.com/Acme` | `smartrecruiters` | `Acme` |
| `acme.wd3.myworkdayjobs.com/...` | `workday` | use `add_workday.py` |

Then pin it:

```yaml
- { name: Acme, slug: acme, sector: freight, size: large, ats: greenhouse }
```

A pinned entry is verified rather than probed, so it costs one request instead of forty.

If the careers URL shows none of these, the employer is on SuccessFactors, Taleo, iCIMS
or a bespoke system. None are supported. Note it and move on.
