Version history

7 October 2026 current

v0.4.6
  • A failed push no longer throws away a good collection. On 7 October run 196 queried all 62 employers, wrote 967 roles, and then failed at the step that commits the result, so the work was discarded with the runner and the feed went stale. The step ran git push once with nothing after it: the cheapest call in the pipeline, at the end of the job, with no tolerance for failure. It now retries three times with a widening pause.
  • Reconciliation is last-write-wins, not a rebase. Between attempts the generated file is set aside, the branch is reset onto whatever the remote holds, and the file is committed again. jobs.json has exactly one writer, so a newer collection is always the right answer and there is nothing to merge — and a rebase conflict in an unattended job would leave the repository stopped half way through a rebase. All four paths through the retry loop were run with git stubbed out before shipping: succeed first time, succeed on the second, succeed on the third, and fail cleanly after three.
  • Every role was being published twice. The feed said 958 roles in scope; there were 480. Deduplication ran correctly and then the loop below it appended each surviving posting to the output list twice, so all four headline figures, every group count and the matched total were exactly double. The two copies were byte-identical, which is why it survived a casual look: nothing on the page contradicted anything else. One line deleted. Figures correct themselves on the next scheduled collection.
  • Correction: this was reported fixed on 5 October and it was not. The change was made to a working copy that never reached the repository, and the claim was published without checking the file it was about. Counting distinct URLs in the feed would have caught it in seconds, which is now the check.
  • The match-reason line says where, not just that. The location test returned its reason — "London", "UK remote" — and the collector discarded it, so every card fell back to the generic "Location accepted". Restored, and also unfixed since 5 October for the same reason as above.
  • The header was broken on a phone, and this is why. The bar is pinned to a fixed 64px so that no page's content can change its height — that is what stopped it moving between pages on a desktop. Below 860px the bar also wraps, and the pin was never released, so a second row of content was being held inside a box still exactly 64px tall. It overflowed and painted on top of the first heading on every page. A fixed height and wrapping cannot both be true; the height is now released at exactly the width where the wrapping begins.
  • The tabs became a scrolling strip. Five tabs cannot share 390px at a legible size, so they now scroll edge to edge, 40px tall for a thumb rather than a cursor, with the current page's tab centred on load. The tab at the right is left half cut by the screen edge on purpose: a clipped tab is the plainest signal that the row moves.
  • Nothing widens the page any more. The uptime strip draws a hundred 2px blocks with 2px gaps, which needs 398px and so pushed the whole page sideways on a phone. It now shows as many of the most recent runs as actually fit and dates itself from the first one shown. The coverage band table scrolls inside its own box. Measured at 320, 393, 430, 768 and 1280px across all five pages: horizontal overflow is zero everywhere and the header no longer overlaps content anywhere.
  • The feed's figures sit two-up on a phone rather than wrapping three-and-one with the fourth stranded on a line of its own.
  • Incident of 5 October resolved. Collections resumed at 22:48 UTC and the entry closed at 00:56 once a second consecutive scheduled run completed, the criterion written down while the incident was still open.
  • Correction: that entry estimated the cost at "roughly two extra hours" of stale data while the outage was still running. The measured gap between successful collections was 5h 55m. Duration is the one field a live incident log should leave empty until it can be measured.

5 October 2026

v0.4.5
  • Status and outages page added, modelled on Atlassian Statuspage, which Slack and Anthropic both use. Current status and uptime are computed live from the GitHub Actions API when the page loads rather than typed in, so they cannot drift from the truth.
  • Collection reliability when the page launched: 171 of 172 scheduled runs since 20 September, median run 69 seconds. The live figure is on the status page; this one is a snapshot and will not be updated.
  • First incident recorded, and still open. On 5 October GitHub stopped allocating runners to this repository. Two jobs queued for fifteen minutes and were cancelled having executed zero steps, and GitHub has an open Actions incident covering it. No application fault and no data loss — each collection is a full refresh, so one successful run restores currency unaided.
  • Correction: this entry first recorded that incident as resolved, on the grounds that a manual collection had been dispatched. The dispatched run then failed the same way on a different runner image. Dispatching a recovery is not recovering, and the status page now says so in its own timeline.
  • The status page separates an active incident from incident history, logs updates newest first, and states its resolution criteria in advance: two consecutive successful scheduled collections, not one, and not GitHub closing its own incident. Defining resolution before you want it is what stops a status page flattering itself.
  • Component rows follow the live banner. The feed row reads Stale while collection is failing, rather than every row claiming operational underneath a red headline.
  • The logotype no longer shifts when you leave the feed. Four pages draw it as a single image; the feed composes it from two SVGs, because only there does the goose animate and change frames. The two agreed on overall height but not on the art grid beneath it — the feed left 5 art units between goose and wordmark where the shared image leaves 8, so the lettering began three units further left, and its unit was typed as 1.70 rather than derived from 46/27. Both now come off the same 27-unit grid.
  • Five dead rules deleted for a masthead and a tagline that no longer exist in the markup. Rules outlive the elements they were written for, and each survivor is somewhere a future change can go wrong invisibly.
  • A third stale duplicate removed, and the pattern named. .alpha was declared twice on all five pages; on the feed the older block sat after the override rather than before it and therefore won, making that badge 2px narrower than the same badge everywhere else. Padding and shadow now come from one declaration. Three survivors of this kind in two days is the argument for one shared stylesheet instead of five copies of it.
  • The status banner states UTC explicitly. It had been rendering the last collection's time in the viewer's own timezone while every timestamp in the incident log beneath it was UTC, so in British Summer Time the same run appeared to happen an hour after the timeline said it did.
  • Two stale CSS rules removed. A duplicate .bar-wrap in the brief put its navigation 8px right of every other page's, and a leftover align-self on the feed's version badge sat it 14px high. Both were survivors of earlier layouts that the newer rules never overrode, which is the usual way a shared header drifts apart.
  • Runner image pinned to ubuntu-24.04. The ubuntu-latest label migrates to Ubuntu 26 from 19 October 2026, and an unattended job should not have its operating system changed underneath it on someone else's schedule.
  • Navigation tabs normalised to equal width, then widened to 146px and forbidden from wrapping. At 138px "Version history" broke onto a second line, which made that one tab taller than the rest and pushed the whole bar down — so the header changed height depending on which page you were on.
  • The bar is now a fixed 64px rather than a minimum, so no page's content can resize it, and the ALPHA badge sits on the same baseline everywhere.
  • The feed's brand lockup rescaled to 46px to match the shared image used on the other four pages. It had been rendering 2px taller, which was the other half of the shifting header.
  • Tagline removed. With five tabs there was no room for it and it was rendering as a single letter and an ellipsis.
  • Correction: moving the collection off the hour to :37 was supposed to shorten GitHub's queue delay. Measured across a fortnight it has not — runs still start 14 to 22 minutes late. The earlier explanation was wrong.

21 September 2026

v0.4.0 → v0.4.3
  • Teamtailor added as a sixth adapter. Eight employers including GXO, Maersk, Geodis and Europcar. It alone moved enterprise reachability from 15% to 22%.
  • Discovery re-run across 211 employers: 62 resolved (29%, from 22%), 5,541 roles assessed, 564 in scope, 7 matched.
  • SmartRecruiters paging fixed. Sixt, Delivery Hero and Grab were each capped at exactly 100 postings. Total supply rose from 3,698 to about 5,500.
  • Recency now uses the employer's publication date where the source provides a trustworthy one. Greenhouse's updated_at is not one, which is why the 24h, 48h and 7d counts had been identical.
  • Seniority split into exec, director and mid-senior. Title exclusions extended to finance, legal, payroll, procurement, talent and HR operations.
  • Two silent data defects fixed: a duplicated line published every role twice, and the geography verdict was computed then discarded.
  • Coverage page added — all 211 employers, reachable or not, by size band and system. Product brief rewritten as a PRD with a stop decision.
  • Interface: shared lockup and a fixed navigation bar across all pages, one control height throughout, filters on one row, stats as a strip, a wider tonal range with a fourth accent hue, crawler exclusion and scheme-checked links.
  • The feed now says what the last collection changed — new and closed counts, or “no change last run”, because a run that changes nothing is evidence the market is still, not that the collector is broken.
  • Tagline replaced. The two-line sector list truncated at every width and said nothing the page did not already show.
  • Collection moved from :00 to :37 after firing 11–17 minutes late on 14 of 14 runs.
Reasoning for these changes is in the product brief. This page records what changed, not why.

20 September 2026

v0.2.0 → v0.3.0
  • The web interface — segmented by employer size, faceted filters, shortlist, dismiss. One file, no framework, no build step.
  • Deployed on Cloudflare Pages from a private repository. GitHub Pro proved unnecessary.
  • Scheduled collection every two hours via GitHub Actions, with a state merge so first_seen survives and roles missing twice are treated as closed.
  • Geography restricted to the UK or remote within GMT ±3, with an impostor guard for London Ontario and similar.
  • Hot filter for roles under 24 hours old; live countdown to the next collection.
  • Mobile Safari: filters collapsed from over half the viewport to 86px, 16px inputs, safe-area insets, dvh units.
  • /site found in the stock Python .gitignore, silently excluding the entire application.
