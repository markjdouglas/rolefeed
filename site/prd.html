Product brief

Summary

RoleFeed polls 62 employers' recruitment systems every two hours and filters for senior operations roles in transport, logistics, mobility and aviation. The mechanism works: around 5,500 live postings, real publication dates, no scraping, nothing to run and nothing to pay. The outcome does not yet: seven roles cleared the filter. The cause is structural rather than a tuning problem, and the next test costs a day.

Built in roughly five scoped hours, deployed and collecting unattended since, at £0 a month on free tiers throughout.

01 Problem

Job boards optimise for the board. Aggregators are slow, duplicated and padded with roles already weeks old, and their filters are too blunt to express a specific search: senior operations, transport and mobility, UK or a workable time zone, above a seniority floor that shifts with company size.

Freshness matters most. Applications land better inside the first 48 hours, before a posting has several hundred applicants. Most tools cannot tell you a posting's age with confidence, so they cannot help you act on it.

02 Approach

Employers publish vacancies through applicant tracking systems, and several of those expose an open, keyless JSON endpoint that the employer's own careers page consumes. Poll a curated list of employers directly and the result is fresher and cleaner than anything downstream of it. Every two hours a scheduled job collects, filters, merges with the previous run so first-seen dates survive, and commits one JSON snapshot. That commit rebuilds a static page.

The constraint that shapes everything

No applicant tracking system offers search. Every endpoint is scoped to one employer, so there is no query to write and nothing to crawl — you can only ask a named employer what it has open. The code is commodity; the curated employer list is the product, and coverage is bounded precisely by who is on it.

So reach is inversely correlated with the target market. Going from 169 employers to 211 moved the rate seven points and left the shape untouched, because a longer list adds reachable and unreachable employers in the same proportion.

04 What the evidence means

The design treated the employer as the unit of coverage, so the obvious lever was a longer list. The unit of coverage is actually the publishing surface the employer sits behind — decided years ago by someone not thinking about job seekers. So the claim worth testing is not about employers:

Any employer that publishes vacancies in machine-readable form on the open web can be collected. The applicant tracking system API is one such surface, and it is the smallest one.

Teamtailor is the evidence. It was written off as closed without being probed, then turned out to publish an open feed with a full schema.org job posting — the best data quality of the six adapters — and on its own moved enterprise reachability from 15% to 22%. Adding an adapter is a day's work with a proven method. Careers-page structured data is the second surface and a larger one, but more work per employer, so it comes second, not first.

The stopping rule

Probe eight more candidate systems, weighted to the UK and enterprise market: Workable, Personio, Pinpoint, Applied, Eploy, Jobtrain, Tribepad, Hireserve. If enterprise reachability does not clear 40%, the ceiling is real, the addressable market for this method is venture-backed technology companies, and the honest conclusion is a well-built tool pointed at the wrong segment. That is a day's work to find out rather than a month's.

05 Roadmap

Under consideration, in dependency order

  • Authentication. Access is URL-only, which is obscurity. It also gates everything below, because both items need state tied to an identity rather than to one browser.
  • Score a role up or down, feeding back into the search. With no endpoint offering search, a signal cannot change a query — there is none. It can widen the employer list, by treating an accepted role as evidence about a sector and size band, and tune the title rules, by showing which patterns yield accepted roles. At a few dozen judgements it is decision support, not a model.
  • Application tracking. Whether a role was applied for, and when. Cheap once state is server-side, and it makes the 48-hour thesis testable rather than assumed.

Both of the latter need durable shared state; shortlists currently live in one browser and do not reach a phone. Against this order: a scoring signal learned from a sample this biased would optimise towards American technology startups. Fix the input first — more adapters, then the Workday employers, then structured data for whatever is left.

06 Limits and non-goals

  • Enterprise coverage is capped by SuccessFactors, Taleo and iCIMS, none of which expose a usable endpoint. Workday is the one covered, and each employer must be hand-configured.
  • Dates are only as good as the source. Four adapters return a real publication date. Greenhouse returns a last-updated timestamp that moves on any edit, so those roles fall back to when RoleFeed first saw them.
  • Undocumented endpoints break silently. A drop to zero roles is treated as suspected breakage, not an empty board.
  • Not a scraper. Where there is no legitimate route — British Airways publishes no feed and disallows its search path — the employer is recorded as uncovered rather than worked around.
  • Not a job board, not an auto-applier, not a framework project. One user, manual applications, one hand-written static file with no build step.
Built to learn how the parts fit together as much as to use it. Three of four success criteria are met; the first — surfacing roles worth applying for — is not yet.
